Navigation and buttons · 23 October 2026

Implemented and checked

The app now uses standard Material 3 navigation. Two tabs, Speed and Trips, replace the loose text links. Sub-screens use a top app bar with a back arrow. The buttons now show which action is most important.

Structure

  • A navigation bar shows the tabs in portrait. A navigation rail shows them in landscape. The tabs show only on their main screens.
  • GPS details, Current trip, and saved trips have a back arrow. Android Back from the Trips tab returns to Speed. Select the current tab again to return to its main screen.
  • Navigation 3 displays an app-owned back stack for each tab. The stacks are saved through rotation and process recreation.
  • The recording notification opens Current trip. A trip that stops elsewhere closes Current trip.

Buttons and controls

  • While a trip is active, a recording bar shows status and time with Pause and Stop icon buttons. In landscape these controls are in the navigation rail.
  • The whole GPS card opens GPS details. A chevron replaces the separate information button.
  • Current trip uses full-width Pause and Stop and save buttons with icons. Trip details opens from the top app bar.
  • Saved trips put Change activity and Delete trip in the top app bar menu. Map controls are 48 dp icon buttons for follow or fit, zoom in, and zoom out.

01Current scope

Implemented

A native Android main screen

  • Jetpack Compose and Material 3.
  • System light and dark themes, with dynamic colour on Android 12 and later.
  • Current speed in km/h, GPS altitude, accuracy, and maximum speed.
  • Portrait and landscape layouts, large text, and screen-reader labels.
  • No home-screen scroll area. The speed display uses the space left by the readings and GPS controls.
  • Precise-location permission, automatic speed display, and recovery actions.
  • Speed and Trips tabs in a navigation bar or rail. The GPS status card opens a scrollable GPS details screen with a back arrow.
  • An abstract satellite ring around the speed uses reported direction and elevation and turns with the phone. A small N marks north. GPS details has a full sky map with direction labels. Brighter markers have stronger signals. Filled markers are used in the position.
  • The position accuracy bar fills from 50 m to 1 m, with a 5 m notch. It does not guarantee accuracy.

GPS with a limited request lifetime

  • Use the Android GPS provider. Request updates once per second.
  • Release the request when the screen becomes inactive, unless a trip is recording.
  • Reject poor readings. Clear readings that are at least 10 seconds old.
  • Keep measurements in SI units. Use the current locale for display.
  • Trips use a location foreground service and local storage. No wake lock or route upload.
  • Home and details share one satellite callback while resumed and GPS is active. Share one location request.
  • Clear old satellite reports after 10 seconds. Animate data changes for 650 ms, with no continuous animation.
  • Run the compass only while a sky display shows satellites and the activity is resumed. Ignore heading changes below one degree.
Performance is a requirement, not a measured result yet. The device tests confirm that GPS stops during pause and inactive display use. An active recording keeps one request after Home or lock. Battery use, startup time, and frame timing still need physical-device measurements.

The local repository contains source, build files, rules, and this report. IDE state, build output, local SDK paths, and prototype exports are excluded. This change remains local. The existing remote was not changed or used for a push.

Trip recording

First functional scope implemented

Record and save

  • Start map tracking from home. Estimate the activity from GPS speed. Correct the trip label if required.
  • Start, Pause, Resume, and Stop. Record after Home or screen lock through a location foreground service.
  • View the live route above the measurements and trip controls. Use the notification after screen lock.
  • Save route points, timestamps, quality fields, and segment boundaries in local Room storage.
  • Open saved trips, review distance and duration, and delete a trip with confirmation.
  • After process loss, show the saved part as interrupted. Resume starts a new segment.

Review the measured route

  • Show saved and interrupted routes with MapLibre 13.7.1 and online OpenStreetMap tiles.
  • Keep manual pauses, process interruptions, signal gaps, and poor positions out of connected route lines.
  • Show start and end markers. Keep map attribution visible on the map.
  • Plane mode shows ground speed, GPS altitude relative to WGS84, true track, and quality. It is a personal record.
  • Use one GPS request with a one-second interval for recording and live readings. Keep historical data separate from display freshness.
  • Trip points stay local. Online tile requests disclose the viewed area to the tile provider.

Field validation remains open. Activity modes currently share one recording policy. The 50 m position threshold and 3 m/s speed-uncertainty threshold need device measurements. Offline maps, specialist map layers, automatic pause, sensor-based activity classification, and elevation totals are deferred.

Read the implementation plan and location power research. The app remains a development build.

Sky ring and map: reported angles, signal brightness, and distinct satellites

Multiple bands with the same system and satellite ID become one marker. Any used band marks that satellite as used. The strongest band supplies the angles. Invalid angles and satellites below the horizon are omitted. The phone heading is subtracted from satellite azimuth and direction-label angles. The home ring keeps the centre clear and adds short links between satellites of one system; the links have no measurement meaning. The details map puts overhead at the centre. Stronger signals are brighter, glow more, and are drawn last. GPS uses circles, GLONASS diamonds, Galileo triangles, and BeiDou squares. Other systems have separate shapes.

val radius = zenithRadius + (1 - zenithRadius) * (1 - elevationRadians / (PI / 2))
val angle = azimuthRadians - headingRadians
